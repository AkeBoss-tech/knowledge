# KRAIL 1.1.13 — OpenSaddle Management Adapters

KRAIL 1.1.13 is the first release that OpenSaddle can manage through bounded,
versioned JSON contracts. It adds reviewed project initialization, health and
reindex operations, and human-approved candidate capture into KRAIL's raw
inbox. None of these adapters can promote content directly to trusted state.

## Highlights

- `krail-admin --contract krail.admin.v1 exchange` implements `init_plan`,
  `init`, `doctor`, and `reindex` with request-bound, idempotent receipts.
- `krail-mutate --contract krail.mutation.v1 exchange` captures one reviewed,
  size-bounded candidate into the raw inbox after verifying its content and
  workspace digests.
- The internal `krail-managed` protocol remains workspace-bound and limits
  file effects to declared KRAIL state.
- Wheels include both adapters, their Python packages, and bundled provider and
  context contract resources.

## Version decision

The public `v1.1.12` tag points to an earlier commit that does not contain the
management adapters. It must not be moved or reused. PyPI currently serves
KRAIL 1.1.1, so this implementation advances directly to 1.1.13.

## Compatibility

- Python 3.11, 3.12, and 3.13.
- OpenSaddle 1.1.0 requires `krail>=1.1.13,<2.0`.
- `rail-mcp` 1.1.13 requires `krail>=1.1.13,<2.0`.
- Existing `rail.yaml` workspaces remain supported. Initialization uses a
  reviewed plan and refuses to apply if the workspace digest has changed.

## Validation before publishing

Run the repository release workflow and the OpenSaddle artifact-integration
workflow. Confirm `twine check` succeeds, both console entrypoints run from a
fresh wheel-only environment, and the lifecycle smoke reaches raw-inbox
candidate capture without importing either source checkout.
